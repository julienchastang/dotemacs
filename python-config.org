#+PROPERTY: header-args :eval yes :results none :tangle yes

* Python

These instructions assume Linux or macOS and a project using ~.venv~.
Follow the project's documented environment and dependency workflow if it
already has one. Run shell commands from the project root.

1. Create the virtual environment if it does not already exist:

   #+begin_src sh :tangle no
   python3 -m venv .venv
   #+end_src

2. Configure automatic activation. Create or update ~.envrc~ to contain:

   #+begin_src sh :tangle no
   source .venv/bin/activate
   #+end_src

   For Bash, add the following line once at the end of =~/.bashrc=,
   then restart the shell:

   #+begin_src sh :tangle no
   eval "$(direnv hook bash)"
   #+end_src

   See [[https://direnv.net/docs/hook.html][Direnv shell setup]] for other shells. Installing Direnv alone
   does not enable shell activation. Emacs uses ~direnv-mode~, enabled below,
   independently of the shell hook.

   Authorize the project environment, then wait for the next shell prompt:

   #+begin_src sh :tangle no
   direnv allow
   #+end_src

   Confirm that Python resolves to this project's ~.venv/bin/python~ before
   installing packages:

   #+begin_src sh :tangle no
   python -c 'import sys; print(sys.executable)'
   #+end_src

3. Install the project's dependencies using its documented commands.
   Common pip workflows are ~python -m pip install -r requirements.txt~,
   ~python -m pip install -e .~ for an installable project, or
   ~python -m pip install -e ".[dev]"~ when it defines a ~dev~ extra.
   A ~pyproject.toml~ file alone does not imply that a project is installable.

   Install development tools into this environment if the project's setup
   has not already supplied them:

   #+begin_src sh :tangle no
   python -m pip install basedpyright ruff pytest
   #+end_src

   The Docker image installs these tools globally, but a default virtual
   environment isolates Python packages. In particular, ~python -m pytest~
   needs pytest installed inside the environment. BasedPyright is the
   preferred language server; Pyright and ~python-lsp-server~ are optional
   alternatives, not additional requirements.

4. Check the tools without running the test suite:

   #+begin_src sh :tangle no
   python -m pip --version
   command -v basedpyright-langserver
   basedpyright --version
   ruff --version
   python -m pytest --version
   #+end_src

   The pip path should be inside ~.venv~. Run ~python -m pytest~ separately
   when ready to execute the project's tests.

5. Open a Python file in Emacs. Run ~M-x direnv-update-environment~ if
   necessary. From that buffer, use ~M-:~ to evaluate each expression:

   #+begin_src emacs-lisp :tangle no
   (getenv "VIRTUAL_ENV")
   (executable-find "python")
   (executable-find "basedpyright-langserver")
   (executable-find "ruff")
   (executable-find "pytest")
   #+end_src

   ~VIRTUAL_ENV~ should name the project's ~.venv~, and Python should resolve
   to its ~bin/python~. The other executables must be found; project-local
   installations should resolve inside ~.venv/bin~.

6. Check Eglot from the Python buffer using ~M-: (eglot-current-server)~.
   A connected buffer should return a server object rather than ~nil~.
   The Python hook starts Eglot automatically; use ~M-x eglot~ if no server
   is connected. After changing the environment, use ~M-x eglot-reconnect~
   for an existing connection. Inspect ~M-x eglot-events-buffer~ for
   connection details or errors.

#+BEGIN_SRC emacs-lisp
  (require 'eglot)
  (require 'company)
  (require 'imenu-list)
  (require 'ruff-format)

  ;; Prefer CAPF-backed completion in Python buffers.
  (setq company-idle-delay 0.1)
  (setq company-minimum-prefix-length 1)
  (setq company-selection-wrap-around t)
  (setq company-tooltip-align-annotations t)

  ;; Shut down Eglot servers when the last managed buffer closes.
  (setq eglot-autoshutdown t)

  ;; Choose Python language server in priority order.
  ;; Keep global setup minimal; prefer project-specific options in
  ;; `.dir-locals.el` via `eglot-workspace-configuration`.
  (add-to-list 'eglot-server-programs
               `(python-mode . ,(eglot-alternatives
                                 '(("basedpyright-langserver" "--stdio")
                                   ("pyright-langserver" "--stdio")
                                   ("pylsp")))))
  (add-to-list 'eglot-server-programs
               `(python-ts-mode . ,(eglot-alternatives
                                    '(("basedpyright-langserver" "--stdio")
                                      ("pyright-langserver" "--stdio")
                                      ("pylsp")))))

  ;; Python IDE wiring for both classic and tree-sitter modes.
  (defun jc/python-eglot-setup ()
    "Enable Eglot, completion, and formatting in Python buffers."
    (eglot-ensure)
    (company-mode 1)
    (ruff-format-on-save-mode 1))

  (add-hook 'python-base-mode-hook #'jc/python-eglot-setup)

  ;; Slim side outline of symbols in the current buffer.
  (setq imenu-list-size 28)

  (setq imenu-list-focus-after-activation nil)
  (setq imenu-list-auto-resize t)
  (global-set-key (kbd "C-c i") #'imenu-list-smart-toggle)

  ;; Handy Eglot actions.
  (with-eval-after-load 'eglot

    (define-key eglot-mode-map (kbd "C-c C-o") #'eglot-code-action-organize-imports))

Direnv

#+BEGIN_SRC emacs-lisp
  (require 'direnv)
  (direnv-mode)
#+END_SRC

The `.envrc` file is a per-project environment definition. When you enter a
project directory, direnv reads this file and exports its variables into your
shell (and thus into Emacs), so tools like LSP and `run-python` pick up the
correct interpreter and PATH without manual activation.

Example `.envrc` for a Python project:

#+BEGIN_SRC sh :tangle no
  source .venv/bin/activate
#+END_SRC

After creating or updating `.envrc`, run `direnv allow` once in that
project so direnv will trust and load the file.

Pytest

#+BEGIN_SRC emacs-lisp
  (require 'python-pytest)

  (defun jc/python-pytest-setup ()
    "Configure pytest keybindings for Python buffers."
    (local-set-key (kbd "C-c t t") #'python-pytest)
    (local-set-key (kbd "C-c t m") #'python-pytest-file)
    (local-set-key (kbd "C-c t f") #'python-pytest-function))

  (add-hook 'python-base-mode-hook #'jc/python-pytest-setup)
#+END_SRC
